# VellumFE Capability Inventory

**Repo**: `.../scratchpad/vellum` — `vellum-fe` v0.3.0-beta.51, GPL-3.0-or-later, author Nisugi, Rust edition 2021. ~310k lines of Rust. Tagline: "modern, high-performance multi-frontend (TUI/GUI) client for GemStone IV". README claims 3,100+ tests. Inspired by ProfanityFE + Wrayth.

## 1. Stated scope (CLAUDE.md, README.md, book/src/SUMMARY.md)
One shared core, **four frontends**: TUI (ratatui), desktop GUI (egui, Wrayth-style look + graphics skins), web ("Despana", browser ESM served by the Rust binary), and headless. Android/iOS build the library `--no-default-features` (core + parser + network + web + headless) and host the web UI. Architectural rules are **mechanically enforced** by `tests/architecture.rs`: core/ and data/ may not import frontend/ or reference egui; core/ stays Android-safe; gui/ must not reference tui/; per-file facade line caps (`parser.rs` ≤1100, `gui/app.rs` ≤3600, `core/app_core/state.rs` ≤2100, `config.rs` ≤700). Data flow: Network → Parser → AppCore → data layer → Frontend. mdBook docs in `book/` (published at nisugi.github.io/VellumFE) cover ~35 widgets, customization, features, in-app editors, config-file reference.

`android/` and `ios/` both exist as full native app shells (Gradle project + `android/rust`; xcodegen `project.yml` + `ios/rust`), workspace members.

**Networking — all three modes** (`src/network.rs`):
- **Lich proxy** (`--port 8000`, recommended in README): TCP to Lich, handshake sends `SET_FRONTEND_PID` (for Lich's window refocus) + FE version string. Handles Lich's detachable-client thread unconditionally prepending `<c>` to commands (so Vellum must send bare commands). Careful about not leaking a reader that would occupy Lich's single detachable-client slot. Tolerates Lich's UTF-8 vs CP1252 encoding bugs (cites lich-5 issues #430, #1533).
- **Lich-launched** (`--key %key%`): sends the login key Lich provides.
- **Direct eAccess, no proxy** (`--direct --account --password --game prime`): does the full login itself — TLS 1.2 to `eaccess.play.net:7910` via `native-tls` with SNI disabled (rustls can't be used: server only offers static-RSA AES128-GCM-SHA256), "K" challenge → 32-byte hashkey → password obfuscation `((p[i]-32)^key[i])+32` → `A\t{account}\t{encoded}\n`. Games: GSIV prime/platinum/shattered/test **and DragonRealms** dr/dr-platinum/dr-fallen/dr-test.
- **`src/launcher/`**: in-app SSH launcher (russh, ring backend, ed25519) that cold-starts a headless `rubyw lich.rbw --detachable-client=PORT` on a home PC over WireGuard/Tailscale, waits for the port, then attaches. Plus a GUI launcher (`--launcher`, default with no args) with saved profiles in `launcher.toml` and passwords in the OS keyring (Windows Credential Manager / Keychain / Secret Service), chacha20poly1305-sealed on Android.
- **`src/webui.rs`**: native WebSocket client for **Lich's WebUI**, rendering Lich WebUI panels natively in the GUI. Discovered via a `;ui handshake` → `<LichWebUI .../>` exchange; auth via `lich_webui=<token>` cookie + allowlisted Origin. Explicitly notes the token is "script-level power (WebUI callbacks run Ruby inside Lich)".

## 3. Parser (`src/parser.rs` facade + `src/parser/`)
Wrayth/Stormfront XML protocol. `KNOWN_WIRE_TAGS` is a sorted 130-ish-entry set (prompt, pushStream/popStream, dialogData/openDialog/component/compDef, compass, roundTime/castTime, left/right/spell, inv, indicator, progressBar, crtrStatus, roomDesc/exits/nav/roommeta, streamWindow, launchURL, LichWebUI, PantheonStatus, container/exposeContainer/deleteContainer, cmdlist, macros, menu/menuLink, presets/palette, settings, worldEvent, objectives/reward, playerID/players, inventoryManager…). ~36 `ParsedElement` variants including Vellum-proprietary extensions (`VellumTimer`, `VellumCommand`, `VellumImage`). Strong invariants: golden-snapshot characterization test (`tests/data/parser_golden.snap`, regen via `UPDATE_PARSER_GOLDEN=1`); nothing silently dropped (unknown tags render literally with `warn!`); streams are a **stack** with `StreamResume`; multi-line `PairedCapture` with 256KiB cap; mangled-markup handling (`$<` is broken server escaping); entities decoded exactly once; live instrumentation via `[parser]` log grep.

**Modeled game state** (`core/state.rs` GameState + related): vitals, room id/name/description-as-styled-lines/exits, compass dirs, game_time from prompt (with local-clock extrapolation so RT counts down through silence), roundtime_end, casttime_end, aimtime, prepared spell, left/right hand, inventory snapshot (styled, with link metadata, plus `inventory_received` to distinguish empty from not-yet), active effects **by category** (ActiveSpells/Buffs/Debuffs/Cooldowns), quest objectives, injuries (body part → level 1-3 wounds / 4-6 scars), status indicators, target list, room creatures / objects / players (each with a generation counter), per-creature derived effects with expiry, mind-state/exp, active streams, custom status. Plus core modules for bounty parsing, bestiary, group, encumbrance, perception, Elanthian time, experience (GSIV + DR variants).

## 4. Scripting / automation / triggers
**No embedded scripting language.** Cargo.toml/Cargo.lock contain no mlua, rhai, rune, deno, boa, quickjs, wasmtime/wasmer, starlark, or Python. Automation is all native Rust:
- **Highlights** (`core/highlight_engine.rs`, `highlights.toml`): regex (+fancy-regex for lookaround) with Aho-Corasick fast literal matching, applied once during message processing before any frontend. Supports **substitutions/replacements** (including window-scoped `DeferredReplacement`), **sound triggers** (`SoundTrigger` with file+volume), and **overlay alert triggers** (`AlertTrigger` with banner text expanded from capture groups, plus cooldown/dedupe identity and alertpacks).
- **Macros** (`macros.toml`), **hotbars** (`hotbars.toml`, condition-driven styling + cooldown countdowns), **keybinds** (`keybinds.toml` with a menu-keybind validator), **gamepad** (`controller.toml`: binds, radial wheels, rumble, tuning; gilrs on desktop, browser Gamepad API on mobile), **cmdlist** substitution, aliases/type-in "insert" buttons that compose phrases client-side.
- **Automation lease** (`core/app_core/automation.rs`): one owner drives the connection; a root-first ownership chain (`foreach` → `go2`), same-kind re-entry allowed, `.stop` cancels the root. Features are `.go2` native travel/pathfinding (`core/travel/`, `core/pathing/` — Dijkstra over the Lich mapdb), `.foreach`/`.sorter` inventory tools, `core/item_mover.rs` (verified moves over Saga's hidden `_drag` verb, confirmed against `<left>`/`<right>` feed rather than prose), skill_trainer/skill_goals, day_pass automation, alert_timers.
- **`.jinx`** (`core/jinx/`): a native federated client for the **Jinx repository protocol** — downloads/updates game data, skins, icon sets, shareable layouts, speaking Jinx's exact wire protocol (SHA1-base64 digests matching Ruby's `Digest::SHA1.base64digest`) so it can read existing elanthia-online repos **without a Lich install**. Nothing auto-downloads unless opt-in.
- ~65 dot-commands (`.menu .addwindow .editwindow .highlights .hl .keybinds .hotbars .themes .skins .settings .streams .webui .controller .go2/.gonew .stop .loadlayout .makeskin .performance` …).

## 5. Config / themes / layout / sound / TTS
Config in `~/.vellum-fe/` (`VELLUM_FE_DIR` override): config.toml, layout.toml, keybinds.toml, controller.toml, hotbars.toml, highlights.toml, colors.toml, macros.toml. Defaults embedded from `defaults/` via `include_dir`; `toml_edit` gives comment-preserving sparse saves; atomic saves with backups; `src/migrate.rs` migrates old layouts; `config/wrayth_import.rs` imports Wrayth settings; profiles + setting scope (global base / per-character override). Every setting has an in-app editor on every frontend. Themes: `src/theme.rs` (4,360 lines) + `theme/loader.rs`, colors.toml palettes, spell colors, plus GUI **graphics skins** (`config/skins.rs`, `skin_pack.rs`, PNG metadata, harmony_skin, a "Vellum Studio" art-calibration mode, AI skin-art prompt docs, and a skin-pack validator CLI used by vellum-assets CI). Layout: `core/layout_engine/` (4,572 lines, spec in `docs/layout-engine-spec.md` + fixtures), window registry/templates, scenes, stage_scene, hotbars, spacers, tabbed windows, stream routing, **shareable UI packs** (`.uiexport`/`.uiimport` zips via `zip` crate). Sound: `src/sound.rs` + rodio (feature `sound`, `--no-sound` flag). TTS: `src/tts/mod.rs` + `tts` crate (feature-gated, stub on non-desktop) — per-window speech, voice/rate control, gag and pronunciation rules, on desktop and phone. Also haptics, custom emoji (animated GIF frames), inline images, room images, creature cards/sprites, maps (classic/curated/mapdb with GitHub-release auto-download so mobile needs no Lich folder), ghost rooms, chokepoints.

## 6. What it relies on Lich for
Vellum works fully **without** Lich (direct eAccess + native mapdb download + native go2 + native jinx asset fetching are all explicitly designed to remove Lich dependencies — `mapdb_update.rs`: "the point on mobile, where there is no Lich folder"). What Lich still buys you:
- **Proxy/detachable-client transport** — attach/detach, sessions surviving phone sleep, multi-device. Vellum handles Lich's `<c>` prefixing, single-slot reader, PID handshake, encoding quirks.
- **`;e <ruby>` eval** — used heavily and non-trivially in `core/pathing/transpile.rs`, `core/travel/executor.rs`, `core/mapdb/`, `core/app_core/commands.rs`, `core/emoji.rs`, `core/layout_engine/scene.rs`. The mapdb's `wayto`/`timeto` edges *are* embedded Ruby (`;e move 'climb rope'; waitrt?`, `;e if checkspell(103) then …`), and Vellum **transpiles** the common idioms to native `WalkAction`s (covers ~1/4 of ~8k scripted edges measured on a real snapshot); the rest (Confluence/event/maze code) stay unroutable natively and are handed to Lich. Also `;e fput`, `;e multifput`, `;e move`, `;e empty_hands`, `;e waitrt`/`waitfor`/`wait_until`, `;e dothistimeout`, `;e group_members`, `;e result`.
- **Other `;`-commands**: `;go2` (fallback when native travel can't route — gated on setting AND a live Lich connection), `;heal`, `;start`, `;bigshot`, `;sellgems`, `;eq`, `;ui handshake`.
- **Lich WebUI** — `;ui handshake` → `<LichWebUI/>` tag, then a native WS bridge rendering Lich's Ruby-backed WebUI panels inside the GUI (advertised as unavailable on direct connections). Notes `LICH_WEBUI_BIND=0.0.0.0` for containerized Lich.
- **SSH launcher** shells out to `rubyw lich.rbw --detachable-client=PORT`.
- Optional local-Lich data dirs for map/gameobj-data/bestiary (`VELLUM_LICH_GAME_DIR` gates `tests/chokepoints.rs`); `gameobj_data.rs` uses fancy-regex specifically to run Ruby-authored regexes; bestiary bakes from lich-5 creature templates.
